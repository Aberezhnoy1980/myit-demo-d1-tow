Состояние: постановка готова, реализация не начата (ждёт разрешения владельца).

## Этапы после разрешения

1. **Каркас и содержание** — `index.html` по структуре задания, весь контент доступен без JS;
   конфиг контактов (один файл, например `config.js` с `window.DEMO_CONTACTS`, значения по умолчанию —
   «не настроено»).
2. **Стили** — `styles.css`: палитра/типографика из docs/design.md, мобильный первый экран,
   адаптация 360/390/768/1440, тёмная тема не требуется, масштаб 200%, липкие элементы не
   перекрывают контакты.
3. **Поведение** — `app.js`: кнопки контактов (configured/unconfigured, проверка URL, fallback
   копирования без Clipboard API), диалог памятки (`<dialog>`: Esc, фокус-трап, возврат фокуса),
   копирование текста обращения.
4. **Проверки** — ручной сценарный протокол (см. docs/brief.md «Проверки»), скриншоты 390/1440 px
   и ключевых состояний, консоль браузера, 404, измерение gzip и веса первого экрана,
   `prefers-reduced-motion`, отказ JS.
5. **Комплект передачи** — README.md, docs/{assets,acceptance,portfolio,report}.md; ответ владельцу:
   как открыть локально, что проверено, скриншоты, ограничения контактов, что нужно для публичного
   выпуска. Общий хэндоф не трогаю (его обновит Codex).

## Зависимости

- Рантайм: нет. Ни пакетных зависимостей, ни сборщика, ни внешних шрифтов/трекеров.
- Локальный просмотр: `python3 -m http.server` (Python 3.11.8 установлен) на 127.0.0.1.
- Проверка размеров: системный `gzip`.
- Скриншоты: Google Chrome 157.0.8103.38 headless, **но под файловой песочницей DSH он падает**
  (его внутренний sandbox и GPU блокируются). Проверенный рабочий вариант:
  `--headless=new --no-sandbox --disable-gpu --user-data-dir=<tmp>` — скриншот 390×844 формируется.
  Альтернатива: владелец снимает скриншоты вручную в обычном Chrome/Safari.
