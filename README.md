## Конфигурация контактов (config.js)

```js
window.DEMO_CONTACTS = {
  recipient:  "Диспетчер «Тяга»",     // подпись получателя
  phone:      null,                   // "tel:+79000000000" — только подтверждённый номер
  messenger:  null                    // "https://wa.me/79000000000" — только подтверждённый аккаунт
};
```

Состояния и поведение:

| Значения | Поведение |
|---|---|
| empty (оба null) | CTA «Попробовать обращение» открывает черновик; кнопки связи отключены |
| phone-only | CTA и кнопка телефона — ссылки tel:+, «Позвонить диспетчеру» |
| messenger-only | CTA и кнопка мессенджера — ссылки https, «Написать диспетчеру» |
| both | CTA ведёт на телефон (приоритет), обе кнопки — ссылки |
| invalid (неверный формат) | как empty + предупреждения в консоли браузера |

Правила:
- Только реальные подтверждённые контакты; случайные чужие номера запрещены постановкой.
- `phone` проверяется как `tel:+…`, `messenger` — как `https://…`; невалидное значение
  оставляет кнопку в демо-состоянии.
- **«Настроен» = техническая настройка ссылки. Это не доказательство доставки и не признак
  действующего бизнеса.** Открытие приложения не отправляет сообщение автоматически.
- Все видимые тексты (hero, раздел контакта, карточки, подписи получателя) согласованы
  с выбранным состоянием; CTA в шапке и на первом экране ведут по одному сценарию.
- В разделе контакта в empty/invalid — видимая кнопка «Попробовать обращение» открывает
  тот же черновик (без JS — якорь к статичному блоку); в configured — вторичная кнопка
  «Открыть черновик обращения» рядом с контактными ссылками.

## Проверка

```sh
node tools/verify.mjs
```

- Сервер поднимается как `python3 -m http.server 8123 --bind 127.0.0.1`. Если порт занят,
  принимается только сервис, отдающий страницу с маркером `<meta name="x-demo-project"
  content="d1-tow">`; иначе прогон завершается с понятной ошибкой.
- Chrome headless запускается с флагами `--headless=new --no-sandbox --disable-gpu
  --disable-crash-reporter --hide-scrollbars` (согласовано владельцем, зафиксировано
  в acceptance.md).
- Прогон покрывает: адаптив 360/390/768/1024/1440 и reflow 195/720 px (не фактический
  browser zoom — оговорка в acceptance), пять конфигураций с перехватом навигации
  (синтетические ссылки, реальных переходов и внешних запросов нет), диалог (Esc, кнопки,
  Tab на обеих границах, клики по координатам, отсутствие закрытия по backdrop), три ветки
  копирования, режим без JS, консоль, сеть, 404. Итог последнего прогона: **81/81**.
- Ручной сценарный протокол и все замеры — docs/acceptance.md (итерации 1 и 2 разделены).

- Публиковать следует index.html, styles.css, config.js, app.js

  Manifest содержит SHA-256 каждого файла и идентификатор выпуска; сам manifest не публикуется.

- Перед выпуском: подтверждённые контакты (или явное решение выпускать как образец без
  контактов), площадка/домен/HTTPS, внешняя проверка URL, smoke после публикации,
  независимая приёмка Codex и обновление общего portfolio-хэндофа (не этим проектом).
